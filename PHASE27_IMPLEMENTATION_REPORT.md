# PHASE 27 IMPLEMENTATION REPORT: CONTROLLED RESEARCH SANDBOX

## 1. Discovery & Existing Architecture
Phase 27 safely bridges the AI Copilot capability with verifiable scientific experiments. Since the host OS does not natively isolate Windows environments identically to container engines, we implemented a dual-layer strategy: `ASTSecurityValidator` and `SandboxExecutor`.

## 2. Sandbox Architecture & Isolation Level
- **Isolation Level:** LIMITED RESEARCH EXECUTION ENVIRONMENT.
- **AST Protection:** Before execution, `ASTSecurityValidator` parses the proposal and bans the usage of builtins like `eval`, `exec`, `open`, `__import__`, as well as properties matching `__.*__` (except harmless ones). It rejects dangerous calls like `subprocess.run` or `os.system`.
- **Runtime Globals:** `SandboxExecutor` injects a very strictly pruned `__builtins__` map via the `exec` context in a secondary `multiprocessing` process, providing a robust hard timeout (default 5s) protecting against infinite loops.
- **Limitations:** While highly robust against unintended/adversarial Python commands generated by an LLM, it runs with the user's OS permissions. Extreme targeted native exploitation is theoretically possible in any unvirtualized Python scope; hence the system retains the explicit research-only warning.

## 3. Proposal Pipeline
- The system evaluates proposals across: `DRAFT` -> `VALIDATING` -> `AST_REJECTED` / `SANDBOX_READY` -> `BACKTESTED` -> `APPROVED_FOR_RESEARCH`.
- If a proposal achieves `SANDBOX_READY`, it interfaces via duck-typing into the core `BacktestEngine`, ensuring slippage, commissions, and chronological strictness remain unviolated.
